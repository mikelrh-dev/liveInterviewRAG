Capítulo 07

Despliegue en Producción

Restricciones reales: Oracle Free Tier ARM64, 4 cores, 24 GB RAM, $0/mes. Sin GPU, toda la inferencia CPU-bound. Nginx y systemd tal como viven en el repositorio.

La restricción: $0/mes

Uno de los objetivos del proyecto era demostrar que se puede construir un sistema de IA funcional sin gastar dinero en infraestructura. Esto es relevante para estudiantes sin presupuesto para GPUs, prototipos donde el costo no debe superar al MVP, y aprendizaje: cuando no puedes escalar con dinero, aprendes a escalar con ingeniería.

Oracle Free Tier ARM64

4Cores ARM64 (Ampere A1)
24 GBRAM compartida (hasta 4 instancias)
$0Costo mensual (siempre-disponible, no trial)

Oracle Cloud Free Tier ofrece cómputo ARM64 con hasta 4 OCPU y 24 GB de RAM siempre gratis. Es suficiente para correr todo el pipeline en carga de conversación única. Solo Whisper consume ~1,4 GB en memoria (valor aproximado del README), así que el margen es holgado para el modelo elegido — la restricción real es tiempo de CPU, no RAM.

ARM64 vs x86

ARM64 es una arquitectura RISC con mejor eficiencia energética. Para inferencia CPU ofrece buen balance precio/rendimiento. CTranslate2 y PyTorch tienen soporte nativo.

Ver también: cómo se eligió entre tamaños de Whisper bajo esta restricción, en el capítulo 02 — Whisper.

Sin GPU: CPU-bound

Sin GPU, toda la inferencia es CPU-bound. El impacto por componente: Whisper STT domina el presupuesto de cada turno (ver capítulo 02), los embeddings de RAG son rápidos (all-MiniLM-L6-v2 está pensado exactamente para esto), y Edge TTS ni siquiera compite por la CPU local: sintetiza en el servicio de Microsoft y devuelve MP3 listo para servir, sin GPU propia.

El README lo resume: el presupuesto del pipeline ronda los 8 segundos en CPU, y es el endpoint de streaming el que hace que la experiencia se sienta responsiva pese a ello.

Nginx: el conf real del repositorio

Este es el contenido de nginx/interview.conf, versión resumida pero fiel:

# nginx/interview.conf (espejo fiel) server { listen 80; server_name _; # Frontend estático servido directamente del disco location / { root /opt/interviewtts/frontend; index index.html; try_files $uri $uri/ /index.html; } # Proxy API → FastAPI location /api/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_buffering off; # crítico para SSE proxy_cache off; } # Audio generado, servido directo con caché corta location /audio/ { alias /opt/interviewtts/audio/; expires 1h; add_header Cache-Control "public, immutable"; } # Cabeceras de seguridad + gzip add_header X-Frame-Options "SAMEORIGIN" always; add_header X-Content-Type-Options "nosniff" always; gzip on; }

Tres detalles que importan:

  • proxy_buffering off: sin esto, Nginx acumula las respuestas en búfer y el streaming SSE se rompe (los eventos llegan a chorros tardíos).
  • /audio/ no pasa por FastAPI: el alias sirve los MP3 directamente del disco con caché de una hora — Python ni se entera.
  • Frontend estático separado: el SPA vive en try_files; solo /api/* toca el backend.

Systemd: la unidad real, con hardening

# deployment/interviewtts.service (espejo fiel) [Service] Type=simple User=interviewtts WorkingDirectory=/opt/interviewtts ExecStart=/opt/interviewtts/venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000 Restart=always RestartSec=5 EnvironmentFile=/opt/interviewtts/.env # Hardening NoNewPrivileges=true ProtectSystem=strict ProtectHome=true ReadWritePaths=/opt/interviewtts/audio /opt/interviewtts/data /opt/interviewtts/reports PrivateTmp=true

El gotcha de ProtectSystem=strict: deja TODO el sistema de archivos en solo lectura salvo lo listado en ReadWritePaths. Sin esa línea, el servicio arranca limpio pero falla la primera vez que toca crear la base SQLite, un MP3 o un informe — un error diferido que solo aparece en producción.

Ver también: qué escribe exactamente el servicio en esos tres directorios, en el capítulo 06 — Persistencia y memoria.

Copia de seguridad

Todo el estado durable cabe en dos rutas: data/interviewtts.db (la base WAL) y reports/ (transcripciones Markdown). Copiar ambas con el servicio detenido — o usando BACKUP de SQLite — captura conversaciones, turnos e informes completos. El audio y la caché de embeddings son regenerables y no merecen espacio de backup.

Hoja de ruta de voz

Pocket TTS y Piper (clonación de voz local, offline) figuran como exploración futura del proyecto. No forman parte del stack desplegado: hoy la voz en producción es Edge TTS.
