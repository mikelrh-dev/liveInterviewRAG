Capitulo 04

LLM y Prompt Engineering

Como reduje el system prompt de 1200 a 600 caracteres, reglas anti-razonamiento, y orquestacion multi-proveedor con degradacion elegante.

El System Prompt

El system prompt es la instruccion fundamental que define como el LLM responde. Es el equivalente a un briefing para un empleado: le dice quien es, que debe hacer, y que no debe hacer.

Empezamos con un prompt de ~1200 caracteres. Tras iterar, lo redujimos a ~600 caracteres. Cada caracter cuenta porque se envia en cada turno, y afecta directamente la latencia y el costo.

Version Final del System Prompt

system_prompt = """Eres un clone digital de un candidato tecnico. Responde como el candidato, no como un asistente. Responde directamente, no expongas razonamiento. Se conciso pero completo. Maximo 2-3 parrafos. Usa terminologia tecnica cuando sea apropiado. Si no sabes algo, di que no tienes esa informacion en tu perfil. No inventes experiencia."""

Note las reglas criticas:

  • "Responde directamente, no expongas razonamiento": Impide que el LLM diga "Voy a analizar tu pregunta..." o "Basandome en mi experiencia..."
  • "Maximo 2-3 parrafos": Limita la longitud para mantener respuestas conversacionales
  • "No inventes experiencia": La linea mas importante para la integridad del sistema

Orquestacion Multi-Proveedor

Usamos dos proveedores de LLM en cascada:

  1. Google AI (Gemini) como proveedor primario
  2. OpenRouter como fallback automatico

Si Google AI falla (rate limit, timeout, error), el sistema automaticamente intenta con OpenRouter. El usuario nunca nota la conmutacion.

Degradacion Elegante

El patron es simple: intenta el proveedor primario, y si falla, intenta el secundario. No hay retry infinito, no hay circuit breaker complejo. Un solo fallback con timeout de 10 segundos es suficiente para nuestro caso de uso.

Streaming Token a Token

En lugar de esperar a que el LLM genere la respuesta completa, hacemos streaming token a token. Cada token generado se envia inmediatamente al TTS para sintetizar.

Esto reduce la latencia percibida dramaticamente: el usuario empieza a escuchar la respuesta antes de que se haya completado la generacion.

# Streaming del LLM async for chunk in llm.stream(prompt, system=system_prompt): audio = tts.synthesize(chunk.text) yield audio # Envia inmediatamente via SSE

Parametros de Generacion

ParametroValorPor que
temperature0.7Balance entre creatividad y coherencia. 0.0 es demasiado robotico, 1.0 es demasiado creativo
max_tokens500Limita respuestas largas. En una conversacion de voz, las respuestas de 2-3 parrafos son ideales
top_p0.9Nucleus sampling: considera el 90% mas probable de tokens, descartando los extremos

Lecciones de Prompt Engineering

  • Menos es mas: Un prompt corto y preciso genera mejores resultados que uno largo y ambiguo
  • Reglas negativas funcionan: Decir "no hagas X" es mas efectivo que describir implicitamente que hacer
  • El contexto del RAG importa mas que el prompt: Un buen contexto recuperado hace que el prompt sea casi irrelevante
  • Testea con preguntas reales: Los prompts que parecen perfectos en papel fallan con preguntas del mundo real
