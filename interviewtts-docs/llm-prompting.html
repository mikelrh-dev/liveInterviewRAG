Capítulo 04

LLM y Prompt Engineering

El system prompt real del gemelo (con su tamaño medido, no estimado), reglas negativas, cascada multi-proveedor condicionada a la clave de API y streaming por frases.

El system prompt

El system prompt es la instrucción fundamental que define cómo responde el LLM: le dice quién es, qué debe hacer y qué no debe hacer. En un gemelo digital tiene una exigencia extra: la respuesta se va a leer en voz alta, así que cada regla del prompt también es una regla de locución.

La plantilla base (CANDIDATE_SYSTEM_PROMPT en backend/prompts/candidate.py) mide 632 caracteres — número contado sobre el código real, no estimado.

La plantilla real, textual

Este es el contenido íntegro de la plantilla, copiado literalmente del repositorio (el marcador {context} se rellena en cada turno con los chunks de RAG y la memoria de conversación):

Eres Mikel, desarrollador junior DAM en una entrevista técnica. Responde DIRECTAMENTE la pregunta. No expongas razonamiento, no digas "Okay" ni "Primero voy a..." — solo responde como un candidato real. Usa primera persona. Reglas: - Conciso por defecto: 1-2 frases. Solo desarrolla (3-4) si te preguntan "cuéntame sobre...", "explícame cómo..." o "¿qué experiencia tienes con...". - Preguntas tipo "¿sabes X?", "¿has usado X?" → 1 frase. - Sé honesto: si no tienes experiencia con algo, dilo con naturalidad. - NO inventes credenciales. - NO uses Markdown ni emojis. Solo texto plano. - Tono profesional pero cercano. {context}

Las reglas críticas, anotadas:

  • "No expongas razonamiento": Impide que el gemelo diga "Voy a analizar tu pregunta..." en voz alta. Un candidato humano no piensa en voz alta estructuradamente.
  • "Conciso por defecto: 1-2 frases": Una respuesta hablada larga mata la conversación. El desarrollo solo llega cuando la pregunta lo pide explícitamente.
  • "NO uses Markdown ni emojis": Doble motivo: rompería la ilusión de voz y, aunque se colara algo, un sanitizador (sanitize_for_tts) limpia Markdown y emojis antes de sintetizar.
  • "NO inventes credenciales": La línea más importante para la integridad del sistema — un gemelo que inventa experiencia es peor que no tener gemelo.

Cascada multi-proveedor, activada por clave

El cliente LLM soporta dos proveedores en cascada:

  1. Google AI (Gemini Flash Lite) como proveedor primario — pero solo si existe GOOGLE_API_KEY.
  2. OpenRouter como destino directo cuando no hay clave de Google, y como respaldo automático ante cualquier excepción del primario.

Este matiz importa: en el .env actual la clave de Google está comentada, así que OpenRouter es el proveedor activo. Definir la clave cambia el routing sin tocar código: Gemini pasa a primario y OpenRouter queda de red de seguridad.

Degradación elegante

El patrón es simple: intenta el primario si está configurado; ante cualquier fallo (rate limit, timeout, error HTTP), intenta el secundario. No hay retry infinito ni circuit breaker complejo. Todas las llamadas comparten un timeout de 60 segundos (httpx.Client(timeout=60.0)).

Streaming: tokens al navegador, frases al TTS

En lugar de esperar la respuesta completa, el backend hace streaming. Pero hay una distinción fina que marca la calidad percibida: los tokens viajan al navegador en cuanto llegan (para pintar el texto en pantalla), mientras que al TTS solo se le envían frases completas:

# Espejo del flujo real: SentenceBuffer (backend/services/llm.py) # + tareas paralelas de TTS por frase (backend/main.py) sentences = sentence_buf.add_token(token) # detecta . ! ? \\n for frase in sentences: clean = sanitize_for_tts(frase) task = asyncio.create_task( tts_service.synthesize_sentence(clean, sentence_id) )

¿Por qué frases y no tokens? Porque Edge TTS necesita la oración entera para entonarla bien: sintetizar fragmentos diminutos produce micro-pausas audibles y multiplica las llamadas de síntesis. Cada frase se sintetiza como tarea paralela mientras el LLM sigue escribiendo; cada MP3 listo sale como evento audio_chunk.

Lecciones de prompt engineering

  • Las reglas negativas funcionan: Decir "no expongas razonamiento" acota el comportamiento mejor que describir vagamente el tono deseado.
  • Medir antes de presumir: "el prompt es corto" es una opinión; "la plantilla mide 632 caracteres" es un dato.
  • El contexto recuperado hace gran parte del trabajo: Con buen RAG, el prompt define el formato y la personalidad; el contenido lo pone la wiki.
  • Testea con preguntas reales: Los prompts que parecen perfectos en papel fallan con preguntas reales dichas en voz alta.
